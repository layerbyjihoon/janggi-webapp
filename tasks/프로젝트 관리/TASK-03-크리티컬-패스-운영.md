# 프로젝트 관리 TASK-03: 크리티컬 패스 운영

## 목적

Gate 통과 이후 세로 슬라이스 구현이 순서대로 진행되도록 의존성과 대기 지점을 관리한다.

## 오너

- PM

## 선행 조건

- `TASK-01-Gate-A-도메인-해석-동결.md`
- `TASK-02-Gate-B-position-key-계약-동결.md`

## 입력물

- 역할별 task 패키지
- `tasks/운영 가이드.md`

## 작업 내용

1. 백엔드 fixture 제출, UX 상태 명세, 프론트엔드 mock loop, QA 테스트 초안의 순서를 조정한다.
2. Checkpoint 1부터 Checkpoint 4까지 승인자를 지정한다.
3. 세로 슬라이스 시연 기준을 `수 적용 -> lookup -> 포진명 표시`로 고정한다.
4. 병렬 진행 중 막히는 작업은 mock 기반 우회 경로로 전환한다.

## 산출물

- 통합 일정 보드
- 체크포인트별 승인 기준
- 우회 경로 메모

## 수용 기준

- 작업 스트림 간 숨은 의존성이 남아 있지 않다.
- 통합 시점마다 누가 승인하는지 명확하다.
- 병렬 작업이 같은 파일이나 같은 계약을 동시에 흔들지 않는다.

## 차단 시 에스컬레이션

- 세로 슬라이스 통합 시점이 연속 두 번 미뤄지면 의존성 재분석을 수행한다.
