# QA TASK-02: lookup과 상태 검증 시나리오

## 목적

등록 포지션, 미등록 포지션, lookup 대기, 시스템 오류 상태를 기능 시나리오로 정리한다.

## 오너

- QA 리드

## 선행 조건

- `TASK-01-fixture-기반-검증-전략.md`
- UX/UI 상태 명세
- 백엔드 응답 예제

## 입력물

- 프론트엔드 상태 전이 문서
- 응답 예제 3종

## 작업 내용

1. 수 적용부터 포진명 노출까지의 검증 타이밍을 시나리오화한다.
2. 등록 포지션과 미등록 포지션의 기대 결과를 분리한다.
3. 시스템 오류가 미등록 상태로 잘못 보이지 않는지 확인 포인트를 만든다.
4. 문서형 UX 잔재 여부를 함께 검사하는 케이스를 포함한다.

## 산출물

- 기능 시나리오 세트
- 상태별 기대 결과 표
- UX 잔재 점검 항목

## 수용 기준

- QA가 실제 UI에서 어떤 타이밍에 무엇을 봐야 하는지 명확하다.
- 미등록과 오류 상태가 테스트 단계에서 구분된다.
- 문서형 잔재가 기능 검증 항목에 포함된다.

## 차단 시 에스컬레이션

- 프론트엔드 상태 전이 타이밍이 불명확하면 시나리오 승인 전 보완을 요청한다.
