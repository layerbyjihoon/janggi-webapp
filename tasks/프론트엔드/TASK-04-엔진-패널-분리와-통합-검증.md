# 프론트엔드 TASK-04: 엔진 패널 분리와 통합 검증

## 목적

엔진 분석 패널을 formation lookup 루프와 분리해 오류 전파를 막고, 세로 슬라이스 통합 기준을 맞춘다.

## 오너

- 프론트엔드 리드

## 선행 조건

- `TASK-03-transposition-반영과-상태-구분.md`

## 입력물

- UX/UI 엔진 패널 분리 가이드
- QA의 엔진 실패 내성 시나리오

## 작업 내용

1. 엔진 Worker 초기화, 분석 중지, 오류 수신 상태를 별도 상태 머신으로 나눈다.
2. 현재 포지션 공유 방식과 formation lookup 상태 공유 방식을 분리한다.
3. 엔진 실패가 metadata 패널에 미치는 영향을 차단한다.
4. QA가 사용할 엔진 실패 내성 검증 절차를 정리한다.

## 산출물

- 엔진 상태 머신 메모
- formation lookup 분리 규칙
- 통합 검증 핸드오프 노트

## 수용 기준

- 엔진 패널 오류가 포진명 표시를 깨지 않는다.
- QA가 엔진 오류와 미등록 포지션을 혼동하지 않도록 검증할 수 있다.
- 세로 슬라이스 데모 기준이 문서화돼 있다.

## 차단 시 에스컬레이션

- 엔진 오류와 lookup 상태가 같은 알림 경로를 공유하면 설계를 재분리한다.
