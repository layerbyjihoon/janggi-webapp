# 한국 장기 연구 웹앱 세부 기획서 - UX/UI

## 1. 역할 목적

UX/UI의 목표는 `연구 문서 관리 화면`을 만드는 것이 아니라 `유저당 하나의 장기 Position Graph를 탐색하고 현재 포진명을 이해하는 작업 공간`을 만드는 것이다. 핵심은 보기 좋은 트리보다 `현재 포지션`, `포진명`, `연결된 수`, `미등록 상태`를 빠르게 이해시키는 것이다.

## 2. 반드시 반영할 제품 규칙

- 사용자는 `새 연구 생성` 흐름을 보지 않는다.
- 사용자는 항상 자신의 단일 그래프 작업 공간으로 진입한다.
- 포진 이름은 착수 이력이 아니라 현재 포지션에 귀속된다.
- 사용자가 한 수를 둘 때마다 현재 포지션의 `primary_formation_name` 또는 미등록 상태가 즉시 보인다.
- 동일 포지션은 도달 경로가 달라도 하나의 노드로 취급된다.

## 3. 레퍼런스 지침

레퍼런스는 아래 두 사이트를 기준으로 삼되, 장기 Position Graph 도구에 맞게 재해석한다.

- `lichess.org`
  보드 중심 레이아웃, 밀도 높은 정보 배치, 사이드 패널의 빠른 탐색 방식을 참고한다.
- `chess.com`
  현재 상태를 명확히 알려주는 라벨링, 클릭 가능한 조작점, 초심자에게 친절한 시각 계층을 참고한다.

적용 원칙:

- `lichess`처럼 보드와 정보 패널을 분리하되, 연구 문서 리스트나 대국 기록 표는 넣지 않는다.
- `chess.com`처럼 현재 포지션 상태는 즉시 읽히게 하되, 도메인 핵심은 `현재 포진명`과 `이웃 포지션 탐색`에 둔다.

## 4. 핵심 화면

### 화면 A. 단일 그래프 작업 공간

필수 요소:

- 장기판
- 현재 포지션의 포진명 영역
- 현재 포지션의 설명 또는 보조 메타데이터 영역
- 현재 포지션에서 가능한 연결 수 또는 인접 포지션 탐색 영역
- 엔진 분석 패널

완료 기준:

- 사용자는 진입 즉시 `현재 포지션`, `포진명 유무`, `다음 탐색 가능 경로`를 알 수 있다.

### 화면 B. 포지션 메타데이터 패널

필수 요소:

- `primary_formation_name`
- `formation_names[]` 보조 노출 여부
- 설명 필드가 유지될 경우 편집 영역
- 미등록 포지션 상태

완료 기준:

- 사용자는 현재 보고 있는 이름이 수순명이 아니라 포지션명이라는 점을 혼동하지 않는다.

### 화면 C. Transposition 반영 상태

필수 요소:

- 서로 다른 경로가 같은 포지션으로 합쳐졌음을 이해시키는 표시
- 현재 포지션의 재사용 노드 개념 설명 또는 암시

완료 기준:

- 사용자가 같은 포지션이 중복 저장되지 않는다는 구조를 UX상 모순 없이 경험한다.

### 화면 D. 미등록 포지션 상태

필수 요소:

- `미등록 포지션` 라벨
- 등록된 포진명이 없는 이유에 대한 짧은 안내
- 등록/편집 가능 여부

완료 기준:

- 포진명이 없다고 해서 오류처럼 보이지 않는다.

## 5. 인터랙션 규칙

### 수 적용과 포진명 갱신

- 사용자가 수를 두면 보드 상태가 먼저 갱신된다.
- 직후 포진명 영역이 새 PositionNode 기준으로 갱신된다.
- 로딩 또는 lookup 대기 상태가 있다면 짧고 명확하게 보인다.

### 포지션 탐색

- 현재 포지션은 항상 강하게 강조한다.
- 직접 연결된 수 또는 이웃 포지션을 우선 노출한다.
- 전체 그래프를 한 번에 강제로 시각화하지 않는다.

### 포진명 표시

- `primary_formation_name`이 있으면 가장 먼저 보여준다.
- 별칭이 있으면 보조적으로 노출하되 기본 정보 구조를 해치지 않는다.
- 이름이 없으면 미등록 상태를 노출한다.

### 엔진 분석

- 엔진 분석은 포진명 패널과 시각적으로 분리한다.
- 사용자가 엔진 평가와 포진명을 혼동하지 않게 라벨을 명확히 둔다.

## 6. 디자인 산출물

- 단일 그래프 작업 공간 와이어프레임
- 포지션 메타데이터 패널 명세
- 미등록/등록/lookup 대기 상태 명세
- transposition 시각 표현 가이드
- 포진명과 엔진 평가 구분 가이드

## 7. 선행 의존성

- `primary_formation_name`과 `formation_names[]` 노출 정책
- 설명 필드 유지 여부
- canonical position 기준과 lookup 타이밍

## 8. 완료 기준

- FE가 현재 포지션 갱신과 포진명 갱신 타이밍을 그대로 구현할 수 있다.
- QA가 등록 포지션, 미등록 포지션, transposition 상태를 문서만 보고 검증할 수 있다.
- 문서형 UX 잔재 없이 단일 그래프 경험이 일관된다.

## 9. 리뷰 체크리스트

- 새 연구/최근 연구 같은 문서형 용어가 남아 있지 않은가
- 현재 포지션의 포진명이 1초 안에 읽히는가
- 미등록 상태가 오류처럼 보이지 않는가
- 같은 포지션 재도달 시 UX가 중복 노드처럼 보이지 않는가
- 엔진 결과와 포진 메타데이터가 명확히 구분되는가
